# Security Policy

Newsmast Foundation takes the security of its software and its hosted
communities seriously. We welcome reports from security researchers,
clients and members, and we will work with you to understand and fix
any issue you find.

## Reporting a vulnerability

Please report security issues privately, using one of these routes:

- **GitHub private vulnerability reporting.** Open the relevant
  repository, go to the **Security** tab, then **Advisories**, and
  choose **Report a vulnerability**. Please do not use public Issues.
- **Email.** Write to <security@newsmastfoundation.org>.

Please do not report security issues in public GitHub issues,
discussions, or on social media. This gives us time to publish a fix
without exposing members to increased risk.

## What to include

A good report helps us act quickly. Where possible, please include:

- the repository, app or community affected, and the version if known
- a description of the issue and its potential impact
- steps to reproduce it, or a proof of concept
- any logs, screenshots or sample requests that help
- how you would like to be credited, if at all

## What to expect

- We acknowledge reports within 3 working days.
- We give an initial assessment within 10 working days.
- We keep you informed of progress until the issue is resolved.
- Once a fix is released, we publish a security advisory and credit
  the reporter, unless you ask us not to.

We ask that you give us reasonable time to release a fix before
disclosing the issue publicly. We do not currently run a paid bug
bounty programme.

## Scope

In scope:

- code in the repositories under the
  [TheNewsmastFoundation](https://github.com/TheNewsmastFoundation)
  organisation
- the Newsmast mobile apps for iOS and Android
- communities and services hosted and operated by Newsmast Foundation,
  including configuration and infrastructure issues

Out of scope:

- vulnerabilities in Mastodon itself. Please report these to the
  Mastodon project through its own security policy. If you are unsure
  where an issue belongs, send it to us and we will pass it on.
- installations of our software run by other organisations. Please
  report issues specific to those installations to their operator.
- denial of service attacks, spam, and social engineering of our staff,
  clients or members
- reports from automated scanners with no demonstrated impact

## Safe harbour

We will not take legal action against, or ask others to take action
against, anyone who reports an issue in good faith and who:

- avoids accessing, changing or deleting data that is not their own
- stops testing and tells us as soon as they come across personal data
- does not disrupt our services or degrade them for members
- does not disclose the issue publicly before we have had reasonable
  time to fix it

## Supported versions

Security fixes are applied to the latest release of each repository.
Communities hosted by Newsmast Foundation are kept on the latest
stable release.
